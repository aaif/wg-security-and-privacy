- **Control surfaces for agent harnesses** — Alex proposed a new deliverable, drafted in [PR #45](https://github.com/aaif/wg-security-and-privacy/pull/45), that builds on the threat modeling, design patterns, and best practices work to propose a standard for control surfaces in agent harnesses such as Claude Code and Cursor. Each harness implements hooks and controls its own way today, and a standard would give harness builders a common interface to adopt and give operators predictable expectations for what a hook can do. Matthew added that the standard should eventually be machine verifiable so compliant harnesses can earn a badge. Alex Khimich asked whether this means a new workstream, and Alex clarified that the aim is a deliverable that an existing workstream could pick up. Alex described the draft as a conversation starter open to any change and noted overlap with work that Alvaro has raised in Identity & Trust.
- **HOL security benchmarks** — Ty Smith shared that HOL plans to release two agnostic security benchmarks within the next month. The first covers context intelligence graphs, testing prompt injection, replay verifiability, and Merkle tree attestation, using CIGAR and the Agent Action Capsule demo as a baseline and comparing against rustworkx and NetworkX. The second benchmarks security harnesses for AI, starting with HOL Guard, an open source harness downloaded about three million times that blocks connected AI from an encrypted local store and provides cryptographic replay proof of human-in-the-loop control. Ty asked which AAIF projects belong in the harness benchmark, and Govindaraj suggested Open Sandbox, Agent Skills, and Open Environment. Ty noted in chat that HOL uses HCS-14 as an agnostic wrapper for agent identity lookup, and Matthew suggested Ty bring the benchmarks to Jordan Auger in the Accuracy and Reliability WG.
- **Runtime governance integration** — Jason Keirstead described a broader effort to define how a policy enforcement point (PEP) and policy decision point (PDP) integrate across every agent runtime surface. OWASP's ACS work covers harnesses, MCP interceptors cover MCP calls at the gateway, AuthZEN covers the identity layer, and sandboxes have no standard at all. Only four of the 25 gateways Jason surveyed support an external PEP, and the MCP interceptor work deliberately excludes inference, which leaves a gap. Jason argued that all four surfaces will persist, so the job is to document how they fit together, and that this groundwork is what makes an AARM-compliant PEP achievable. Alex Khimich suggested scoping a deliverable to PDP and PEP integration and leaving identity and access controls to other working groups, and Jason agreed that runtime policy stands apart from identity. Marc expects several of these efforts to succeed as separate standards and welcomed coordinating them.
- **Kill switch ownership** — Marc supported the control surfaces proposal and described the kill switch as a pillar of security whose scope runs from cutting the signal between the LLM and the agentic loop to binding the two together. Marc sees Identity & Trust as too broad and horizontal to own it, noted that Identity & Trust is considering a separate group for delegation, and offered to help write the kill switch up as a principle. Alex Khimich proposed a three-part mental model, with identity, delegation, access controls, and kill switch as one area, PDP and PEP integration around harnesses as the second, and auditability with machine verification as the third, and asked which working group owns the first area. In chat, Alex Khimich separated an access kill switch, which belongs to authorization, from an agent kill switch, which belongs to the harness environment, and pointed to Section C, Agent Control and Containment, in the running notes doc. Matthew observed that kill switches could reasonably live in Accuracy and Reliability, Security and Privacy, or Identity and Trust, which makes them a hot potato, and Francesco confirmed the kill switch is an unowned seam in the Agentic standards map and will add it there. Govindaraj suggested an official list of these items that names an accountable owner and supporting stakeholders for each, and Alex will collect the seams and bring them to the next chairs meeting.
- **Charter review** — Monique suggested reviewing and harmonizing the working group charters so each one states what it covers and what it leaves to others. Alex agreed that six months since charter approval is an eternity in this ecosystem and will raise a charter review at the next chairs meeting. Matthew noted the groups now have the experience to take a better second pass, and Dawn offered in chat to help with charter alignment across all working groups.
- **Agent Gateway reference implementation** — Govindaraj raised concerns that the Agent Gateway reference implementation assumes Kubernetes, lacks support for serverless functions, managed agent platforms from AWS, Google, and Azure, and SaaS platforms such as Salesforce, and logs to Postgres without following the observability and tracing work. Fernando offered to share a comparison of the three cloud agent platforms.

Speakers from Google, AWS, and Solo.io are lined up, and EY and a UT Dallas student will demonstrate agent authentication and authorization with PEP and PDP using Cerbos, AGNTCY directory identity, and OpenID verifiable credentials. Govindaraj is seeking more speakers on runtime protection, harnesses, and identity, noted that the event cannot fund speaker travel, and will share the link once it is posted. Muhammad would like to present remotely, and virtual streaming depends on logistics.
